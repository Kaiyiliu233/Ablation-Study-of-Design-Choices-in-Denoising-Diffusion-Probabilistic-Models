# DDPM ablations on CIFAR-10

We referenced the following PyTorch implementations for guidance:
- Openai/improved-diffusion: https://github.com/openai/improved-diffusion/
- Kaggle, DDPM from Scratch: https://www.kaggle.com/code/vikramsandu/ddpm-from-scratch-in-pytorch

## How we used generative AI
For the code, we wrote the first version ourselves by reading the DDPM paper and the two implementations linked above. We then used Claude to help clean things up, catch bugs, and reorganize the project into the file layout. The core logic (schedules, forward process, U-Net, training loop) was written by us and then refined together with Claude.

For the paper, we wrote the first draft ourselves. Claude was used for grammar checks and small feedback on phrasing. We also used it for clean Latex formatting on Overleaf. No content or arguments were generated by it.

## Files
- `config.py`: experiment parameters and the list of runs
- `diffusion.py`: forward process and sampler
- `model.py`: U-Net
- `train.py`: training loop
- `eval.py`: sampling images from a checkpoint (for FID)

## Setup
Needs PyTorch, torchvision, and `ema-pytorch`. CIFAR-10 will be downloaded into `./data` on first run.

```
pip install torch torchvision ema-pytorch
```

## Train
Pass a run name or an experiment group from `config.py`.

```
python train.py exp1_schedule_cosine
python train.py exp1_schedule
```

Checkpoints will be saved in `checkpoints/<exp>/` and sample grids in `samples/<exp>/`. If a checkpoint already exists for that run, training resumes from it.

## Sample for FID
After training, generate a folder of images from a checkpoint.

```
python eval.py exp1_schedule_cosine --n 10000
```

Use `--step` to pick a specific checkpoint, otherwise it grabs the latest. If the run used EMA, the EMA weights are loaded automatically.

Note: we could not fit every checkpoint and FID sample folder in this repo due to Git LFS storage limits, so only a representative subset is included.
